# Лутик — общая комната

Сайт, на котором люди на расстоянии складывают объекты в одно пространство
и видят действия друг друга.

Node.js на своей машине не нужен: и сборка, и выкладка происходят в облаке.

## Что куда

```
.github/workflows/deploy.yml   автовыкладка при пуше (запасной путь, см. ниже)
public/                        статика: страница, стили, скрипт, объекты библиотеки
src/index.js                   Worker и комната
wrangler.jsonc                 конфиг Worker + Durable Object
package.json                   зависимости (ставятся в облаке при сборке)
package-lock.json              фиксирует версии
.gitignore                     node_modules, .wrangler, .DS_Store
```

Всё, что лежит в этой папке, кладётся в git целиком — секретов здесь нет.
`node_modules` нет и не нужно: зависимости ставятся на стороне сборки.

## 1. Залить на GitHub

1. github.com → **New repository** → имя, например `lutik` → **Create**.
2. На пустой странице репозитория: **uploading an existing file**.
3. Перетащить туда содержимое этой папки — папки `public`, `src`, `.github`
   и файлы рядом с ними.
4. **Commit changes**.

Точечно: в Finder скрытые файлы (`.gitignore`, `.github`) показываются
по `⌘ + Shift + .` — без этого они не перетащатся.

## 2. Выложить на Cloudflare

### Путь А — Cloudflare собирает сам

1. dash.cloudflare.com → **Workers & Pages** → **Create** → вкладка **Workers**
   → **Import a repository**.
2. Подключить GitHub, выбрать репозиторий.
3. Команды:
   - **Build command**: `npm install`
   - **Deploy command**: `npx wrangler deploy` (значение по умолчанию)
4. **Create and deploy**.

Cloudflare сам поставит зависимости, применит миграцию Durable Object
и выложит Worker. Дальше каждый пуш в `main` пересобирает его автоматически.
Адрес будет вида `https://lutik-room.<твой-поддомен>.workers.dev`.

### Путь Б — собирает GitHub

Если подключение репозитория недоступно, в проекте уже лежит
`.github/workflows/deploy.yml` — он делает то же самое на стороне GitHub.

1. dash.cloudflare.com → **My Profile** → **API Tokens** → **Create Token**
   → шаблон **Edit Cloudflare Workers** → скопировать токен.
2. В репозитории: **Settings** → **Secrets and variables** → **Actions**
   → **New repository secret**, имя `CLOUDFLARE_API_TOKEN`, значение — токен.
3. Вкладка **Actions** → workflow «Deploy to Cloudflare» → **Run workflow**.

Дальше тоже само: пуш в `main` → выкладка.

### Локально (если Node всё-таки появится)

```bash
npm install
npm run dev        # http://localhost:8787
npm run deploy
```

## Как это устроено

Один Worker (`src/index.js`):

- всё, что не `/api/*`, отдаётся из `public/` как статика с края сети;
- `/r/<id>` отдаёт `index.html` (режим SPA), маршрут разбирает клиент;
- `/api/rooms` создаёт комнату, `/api/rooms/<id>/...` уходит в её Durable Object.

**Одна комната = один Durable Object** с SQLite внутри. Таблицы:

| таблица   | что хранит                                                        |
|-----------|-------------------------------------------------------------------|
| `meta`    | имя комнаты и фон                                                 |
| `users`   | роли: имя + цвет, без паролей                                     |
| `objects` | что лежит в комнате: картинка, позиция, размер                    |
| `blobs`   | свои картинки, сжатые на клиенте в webp                           |
| `events`  | журнал изменений — из него собираются диффы                       |

### Синхронизация

Любое изменение пишется в `events` и тут же уходит во все открытые вебсокеты.
Клиент держит у себя номер последнего применённого события (`seq`), поэтому:

- пришло событие по сокету → применили, сдвинули `seq`;
- сокет отвалился → раз в секунду опрашиваем `/state?since=<seq>` и добираем диффы;
- отстали слишком сильно (журнал успел подрезаться) → сервер отдаёт полный снимок.

То есть вебсокет — это быстрый путь, а опрос диффов раз в секунду — запасной.
Порядок событий задаёт сервер, так что расхождений между участниками не бывает.

### Картинки

Пользователь может выбрать файл до 10 МБ. Клиент жмёт его в webp прямо в браузере
(сначала убавляя качество, потом размер), пока не влезет в ~1.5 МБ для фона
и ~0.8 МБ для объекта. На сервере потолок 2 МБ: SQLite в Durable Object
перестаёт принимать значения где-то между 3 и 5 МБ.

### Приватность

Пароля нет: id комнаты — 22 символа из алфавита в 57 знаков, это ~128 бит.
Перебрать нельзя, но у кого ссылка — тот внутри и может удалять чужие объекты.
